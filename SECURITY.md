# Reporte responsable de vulnerabilidades

No publicar vulnerabilidades explotables, datos de menores, credenciales ni
evidencia real en issues o Pull Requests. Abrir un reporte privado al
administrador mediante GitHub Security Advisories. Si esa función no está
habilitada, contactar al propietario del repositorio por un canal privado antes
de divulgar el problema.

Incluir versión o commit, pasos mínimos de reproducción, impacto, evidencia
sanitizada y una propuesta de mitigación. No incluir secretos ni información
personal real.

Las versiones soportadas son `main` y la última versión etiquetada disponible.
Las ramas históricas no reciben soporte operativo.
